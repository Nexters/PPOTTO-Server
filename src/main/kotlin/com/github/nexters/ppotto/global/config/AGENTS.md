# global.config

Spring configuration beans.

| File | Description |
|------|-------------|
| `CorsConfig.kt` | Declares `corsConfigurationSource` from `CorsProperties`: every method and header, `allowedOriginPatterns`, no credentials (authentication is a Bearer header, never a cookie, so a wildcard origin is safe). The security filter chains themselves live in `auth/config/AuthSecurityConfig.kt` |
| `PublicPaths.kt` | Single source of truth for public paths. Exposes ant patterns (`PUBLIC_API_PATTERNS`, `DOCUMENT_PATTERNS`) for the security chains and exact/prefix matchers (`isPublicApi`, `isDocument`) for `BearerTokenAuthenticationFilter.shouldNotFilter`, so the chain and the filter can never drift apart. `OPTIONAL_AUTH_GET_PATTERNS` covers the separate optional-auth case: those GETs are permitted anonymously by the chain but still pass through the Bearer filter, so a supplied token is resolved and the handler can tell owner from stranger. There is deliberately no `isOptionalAuthGet` predicate — the filter must *not* skip those paths, so nothing would call it; `PublicPathsTest` pins that pattern-versus-predicate agreement instead |
| `CorsProperties.kt` | `@ConfigurationProperties("cors")` + `@Validated`. Bound from `CORS_ALLOWED_ORIGINS` and applied as `allowedOriginPatterns`; production sets `*` |
| `ApiVersions.kt` | `object`. Single source of truth for the API version policy: the header name (`API_VERSION_HEADER`), the server default (`DEFAULT_API_VERSION`), `SUPPORTED_API_VERSIONS`, the declared `@RequestMapping(version = ...)` of a handler type (`declaredVersionOf`), whether it is pinned rather than baseline (`isVersionPinned`), and which versions it accepts (`acceptedVersionsOf`). `WebMvcConfig`, `OpenApiConfig`, and `ApiVersioningTest` all read it, so the runtime config, the docs, and the regression guard can never disagree with the mappings |
| `OpenApiConfig.kt` | Swagger metadata, response envelope contract, the common error table generated from `CommonErrorCode.entries` (never hand-copied), Bearer scheme, and fluent required/optional authentication documentation inferred from controller argument annotations. `apiVersionHeaderCustomizer` only rewrites the `X-API-Version` parameter that springdoc already derives from the Spring versioning config; it never adds a second one. `v1ApiGroup`/`v2ApiGroup` publish one `GroupedOpenApi` per version, filtered by `acceptedVersionsOf`, each pinning the header to its own version. `operationCustomizer` attaches the shared `COMMON-004` example to the 401 it injects through `ApiExampleFactory`, so it uses the same production `ObjectMapper` as every other example. `Info` carries no `version`: the document is published per API version as `v1`/`v2` groups, so a single document-level version could only be wrong |
| `WebMvcConfig.kt` | Header versioning (`ApiVersions.API_VERSION_HEADER`, default `ApiVersions.DEFAULT_API_VERSION`) and `CurrentUserArgumentResolver` registration. Supported versions are detected from the mappings themselves, so declaring a new version anywhere makes it globally supported |
| `GcsProperties.kt` | `@ConfigurationProperties("gcs")` + `@Validated`. `bucket`, `credentialsPath`, `uploadSignedUrlExpirationMinutes` (15 min per spec), `readSignedUrlExpirationMinutes` (60 min per spec — read/GET signed URLs expire differently from upload URLs, so they are separate properties), `timeoutMillis` — bound from `GCS_*` env vars. Both expirations are capped at 24h, the GCS V4 signing limit |
| `TransactionConfig.kt` | Declares the shared `transactionTemplate` bean (no timeout, same as the Boot default). Boot's `TransactionAutoConfiguration.transactionTemplate` is `@ConditionalOnMissingBean(TransactionOperations)`, so it backs off as soon as auth's dedicated `signupTransaction` bean exists. This declares the shared template explicitly for the code that still uses it (`AnalysisService`). Also carries `@EnableTransactionManagement(proxyTargetClass = true, order = TRANSACTION_ADVICE_ORDER)` and owns the `TRANSACTION_ADVICE_ORDER` constant |
| `GcsConfig.kt` | Defines the `Storage` bean. Authenticates by reading the service account key file (`gcsProperties.credentialsPath`) via `ServiceAccountCredentials.fromStream` — not the `GOOGLE_APPLICATION_CREDENTIALS` ambient method. Sets connect/read timeout (`gcsProperties.timeoutMillis`) via `HttpTransportOptions` so a slow/hanging GCS call can't block indefinitely |
| `AsyncConfig.kt` | `@EnableAsync` plus named executor beans, one bean name per pipeline, declared twice: a virtual-thread-backed `SimpleAsyncTaskExecutor` under `@Profile("!test")` and a `SyncTaskExecutor` under `@Profile("test")`, so async results are deterministic in tests without touching production code. `analysisCleanupTaskExecutor` is used by `analysis/application/AnalysisCleanupEventListener`; `stickerImageCleanupTaskExecutor` by `sticker/application/StickerImageCleanupEventListener`, so post-regeneration image deletes stay off the request thread; `analysisPipelineTaskExecutor` by `analysis/application/AnalysisPipelineEventListener`, so `POST /analysis/{id}/start` returns at the `UPLOADING → ANALYZING` transition; `pushNotificationTaskExecutor` by `notification/application/PushNotificationEventListener`, so FCM delivery never blocks the caller |
| `HttpServiceClientConfig.kt` | Pins every `@ImportHttpServices` group's (pixian, oauth, ...) RestClient to the JDK built-in HttpClient via `JdkClientHttpRequestFactory`. Spring picks a request factory off the classpath automatically, so adding a library such as Apache HttpClient5 would silently switch every external call to a client that retries 5xx on its own — stacking on top of the call site's explicit retry and multiplying the real request count. Fixing one factory keeps external call behaviour independent of which dependencies are present |

## Rules

- **Declaring `@EnableTransactionManagement` explicitly is what replaces Boot's auto-configured transaction advice, and the point of doing so is the `order`.** Boot's `TransactionAutoConfiguration` leaves the advisor at `Ordered.LOWEST_PRECEDENCE`, and nothing can be ordered *inside* the lowest precedence — an around-advice that needs an already-open transaction (`global/lock/AdvisoryLockAspect`, at `TRANSACTION_ADVICE_ORDER + 100`) would run outside it and fail its own `check`. `proxyTargetClass = true` keeps CGLIB proxying, which is what Kotlin classes without interfaces need. Changing either value silently changes advice nesting for every annotated method, so `global/config/TransactionAdviceOrderTest` pins both the advisor count and the order.
- Adding a new `TransactionOperations` bean makes Boot's shared `transactionTemplate` auto-configuration back off. Do not delete `TransactionConfig.transactionTemplate`, and inject domain-specific beans with `@Qualifier` instead of relying on name fallback so there is no ambiguity.
- New `XxxProperties` classes follow the CorsProperties pattern: data class, constructor binding, `@Validated` + jakarta constraints. Separate annotated constructor property groups with one blank line.
- Every `@Configuration` class here declares `proxyBeanMethods = false`. No bean method in this package calls another bean method, so the CGLIB subclass buys nothing and only slows startup. Keep new ones consistent; if a config ever genuinely needs inter-bean method calls, take the dependency as a method parameter instead of turning the proxying back on.
- Every named executor bean in `AsyncConfig` is declared twice under mutually exclusive profiles, with the **same bean name**. Never add a `!test`-only executor: `@Async("name")` with no matching bean in the `test` profile falls back to the default executor, and pipeline assertions become timing-dependent.
- Security chain ordering, the mutually exclusive chain profiles (`!test | secured` for the production API chain, `test & !secured` for the permit-all test fallback — `AuthSecurityChainTest` activates `secured` to run the real chain in tests), and the 401/403 envelope handlers are documented in `auth/AGENTS.md` (`config/AuthSecurityConfig.kt`).
- `GET /terms` and `GET /stickers/shared/{shareToken}` are the only anonymous-accessible endpoints, and they stay out of `isPublicApi` on purpose: `shouldNotFilter` would skip Bearer authentication entirely, so a supplied-but-invalid token would slip past instead of failing. `POST /terms/agreements` and every sticker endpoint including `GET /stickers/{stickerId}` remain protected. `PublicPathsTest` fails if a predicate and its ant pattern ever disagree, so adding a path means adding it to both.
- Don't mark beans that read local files/external credentials (e.g. `GcsConfig.storage`) `@Lazy`. Every integration test in this repo (extending `IntegrationTest`) boots the **entire** application context via `@SpringBootTest`, so instead of scattering `@Lazy` through production code to dodge test startup, provide a real, parseable dummy credentials file in tests (`src/test/resources/dummy-gcs-key.json`) so the bean can be created eagerly as normal. Building the `Storage` bean and V4-signing are local credential parsing / RSA signing operations with no network call, so a dummy key is enough. Follow this same pattern (keep the real bean as-is, add a dummy test fixture) for any new bean that reads local files or external credentials.

- **Every mapping that does not change between versions declares a baseline version (`version = "1+"`), never a fixed one.** Spring detects supported versions from the mappings, so the moment one mapping declares `"2"` the whole application accepts version 2 — and a mapping fixed at `"1"` then answers a v2 request with `NotAcceptableApiVersionException` (400). Only an endpoint that has a v2 replacement at the same path and method may stay fixed at `"1"`. `ApiVersioningTest` fails when a fixed mapping has no sibling accepting every supported version, so a new endpoint pinned to `"1"` cannot ship.
- `VersionRequestCondition.getMatchingCondition` compares baselines even for a fixed version; the fixed-version rejection happens later in `handleMatch`. Never assert reachability with `getMatchingCondition` — use `acceptedVersionsOf`.
- Two mappings on the same path and method (one per version) cannot both appear in one OpenAPI document, so the ungrouped `/v3/api-docs` shows only one of them. The per-version documents at `/v3/api-docs/v1` and `/v3/api-docs/v2` are the ones clients read.
- Rewrite the `X-API-Version` parameter from an `OpenApiCustomizer`, not an `OperationCustomizer`. springdoc fills the parameter in after operation customizers run and appends its own parsed value (`1` becomes `1.0.0`), so an operation-level rewrite ends up with both values in the enum.

Update this file when configuration beans change.
