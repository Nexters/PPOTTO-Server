# global.config

Spring configuration beans.

| File | Description |
|------|-------------|
| `SecurityConfig.kt` | Swagger chain (`@Order(0)`, prod Basic), stateless JWT Bearer API chain (`@Order(100)`, `@Profile("!test")`), test-only permit-all fallback chain (`@Profile("test")`) that still runs `BearerTokenAuthenticationFilter` explicitly via `addFilterBefore`, a disabled `FilterRegistrationBean` that turns off the filter's servlet auto-registration so the filter only runs inside security chains, and fluent CORS source construction. Login, refresh, health, swagger, and the optional-auth GET paths (`GET /terms`, `GET /stickers/{stickerId}`) are public; all other API requests require authentication |
| `PublicPaths.kt` | Single source of truth for public paths. Exposes ant patterns (`PUBLIC_API_PATTERNS`, `DOCUMENT_PATTERNS`) for the security chains and exact/prefix matchers (`isPublicApi`, `isDocument`) for `BearerTokenAuthenticationFilter.shouldNotFilter`, so the chain and the filter can never drift apart. `OPTIONAL_AUTH_GET_PATTERNS` / `isOptionalAuthGet` cover the separate optional-auth case: those GETs are permitted anonymously by the chain but still pass through the Bearer filter, so a supplied token is resolved and the handler can tell owner from stranger |
| `CorsProperties.kt` | `@ConfigurationProperties("cors")` + `@Validated`. Bound from `CORS_ALLOWED_ORIGINS`. Values are applied as `allowedOriginPatterns` (not `allowedOrigins`) because `allowCredentials = true` forbids the literal `*` in `allowedOrigins`; exact origins still match as-is, and Dev sets `*` to allow every origin |
| `ApiVersions.kt` | Single source of truth for the API version policy: `SUPPORTED_API_VERSIONS`, the declared `@RequestMapping(version = ...)` of a handler type (`declaredVersionOf`), whether it is pinned rather than baseline (`isVersionPinned`), and which versions it accepts (`acceptedVersionsOf`). `OpenApiConfig` and `ApiVersioningTest` both read it, so docs and the regression guard can never disagree with the mappings |
| `OpenApiConfig.kt` | Swagger metadata, response envelope contract, common error table, Bearer scheme, and fluent required/optional authentication documentation inferred from controller argument annotations. `apiVersionHeaderCustomizer` only rewrites the `X-API-Version` parameter that springdoc already derives from the Spring versioning config; it never adds a second one. `v1ApiGroup`/`v2ApiGroup` publish one `GroupedOpenApi` per version, filtered by `acceptedVersionsOf`, each pinning the header to its own version. `operationCustomizer` attaches the shared `COMMON-004` example to the 401 it injects through `ApiExampleFactory`, so it uses the same production `ObjectMapper` as every other example |
| `WebMvcConfig.kt` | `X-API-Version` header versioning with default `1` and `CurrentUserArgumentResolver` registration. Supported versions are detected from the mappings themselves, so declaring a new version anywhere makes it globally supported |
| `GcsProperties.kt` | `@ConfigurationProperties("gcs")` + `@Validated`. `bucket`, `credentialsPath`, `uploadSignedUrlExpirationMinutes` (15 min per spec), `readSignedUrlExpirationMinutes` (60 min per spec — read/GET signed URLs expire differently from upload URLs, so they are separate properties), `timeoutMillis` — bound from `GCS_*` env vars. Both expirations are capped at 24h, the GCS V4 signing limit |
| `PixianProperties.kt` | `@ConfigurationProperties("pixian")` + `@Validated`. API id/secret, test mode, and remove-background URI are bound from `PIXIAN_*` env vars; the analysis domain owns the HTTP service registration and adapter |
| `VertexAiProperties.kt` | `@ConfigurationProperties("vertexai")` + `@Validated`. Project/location plus separate classification and verification timeout budgets are bound from `VERTEX_AI_*` env vars; verification intentionally has its own shorter timeout because it is a quality guard with classification fallback. Sticker cutout no longer calls a Vertex AI image model, so there is no sticker-generation timeout property |
| `TransactionConfig.kt` | Declares the shared `transactionTemplate` bean (no timeout, same as the Boot default). Boot's `TransactionAutoConfiguration.transactionTemplate` is `@ConditionalOnMissingBean(TransactionOperations)`, so it backs off as soon as auth's dedicated `signupTransaction` bean exists. This declares the shared template explicitly for the code that still uses it (`AnalysisService`) |
| `GcsConfig.kt` | Defines the `Storage` bean. Authenticates by reading the service account key file (`gcsProperties.credentialsPath`) via `ServiceAccountCredentials.fromStream` — not the `GOOGLE_APPLICATION_CREDENTIALS` ambient method. Sets connect/read timeout (`gcsProperties.timeoutMillis`) via `HttpTransportOptions` so a slow/hanging GCS call can't block indefinitely |
| `AsyncConfig.kt` | `@EnableAsync` plus named executor beans. `analysisCleanupTaskExecutor` is used by `analysis/application/AnalysisCleanupEventListener`; `stickerImageCleanupTaskExecutor` is used by `sticker/application/StickerImageCleanupEventListener` so post-regeneration image deletes stay off the request thread. `analysisPipelineTaskExecutor` is used by `analysis/application/AnalysisPipelineEventListener`; non-test profiles use a virtual-thread-backed `SimpleAsyncTaskExecutor` so `POST /analysis/{id}/start` returns at the `UPLOADING → ANALYZING` transition, while the `test` profile uses `SyncTaskExecutor` so pipeline result assertions are deterministic |

## Rules

- Adding a new `TransactionOperations` bean makes Boot's shared `transactionTemplate` auto-configuration back off. Do not delete `TransactionConfig.transactionTemplate`, and inject domain-specific beans with `@Qualifier` instead of relying on name fallback so there is no ambiguity.
- New `XxxProperties` classes follow the CorsProperties pattern: data class, constructor binding, `@Validated` + jakarta constraints. Separate annotated constructor property groups with one blank line.
- The JWT chain stays at `API_CHAIN_ORDER`; keep swagger Basic auth ahead of it and the fallback chain last.
- The API chain and the permit-all fallback chain both match any request, so their profiles must stay mutually exclusive (`@Profile("!test")` / `@Profile("test")`). If both are ever active, Spring Security aborts context refresh with `UnreachableFilterChainException` — which no test catches, because tests only run the `test` profile.
- 401/403 from the JWT chain use the same `ApiResponse` error envelope through auth security handlers.
- `GET /terms` and `GET /stickers/{stickerId}` are the only anonymous-accessible endpoints, and they stay out of `isPublicApi` on purpose: `shouldNotFilter` would skip Bearer authentication entirely and the handler could no longer resolve `@CurrentUser`. `POST /terms/agreements` and every other sticker endpoint remain protected.
- Don't mark beans that read local files/external credentials (e.g. `GcsConfig.storage`) `@Lazy`. Every integration test in this repo (extending `IntegrationTest`) boots the **entire** application context via `@SpringBootTest`, so instead of scattering `@Lazy` through production code to dodge test startup, provide a real, parseable dummy credentials file in tests (`src/test/resources/dummy-gcs-key.json`) so the bean can be created eagerly as normal. Building the `Storage` bean and V4-signing are local credential parsing / RSA signing operations with no network call, so a dummy key is enough. Follow this same pattern (keep the real bean as-is, add a dummy test fixture) for any new bean that reads local files or external credentials.

- **Every mapping that does not change between versions declares a baseline version (`version = "1+"`), never a fixed one.** Spring detects supported versions from the mappings, so the moment one mapping declares `"2"` the whole application accepts version 2 — and a mapping fixed at `"1"` then answers a v2 request with `NotAcceptableApiVersionException` (400). Only an endpoint that has a v2 replacement at the same path and method may stay fixed at `"1"`. `ApiVersioningTest` fails when a fixed mapping has no sibling accepting every supported version, so a new endpoint pinned to `"1"` cannot ship.
- `VersionRequestCondition.getMatchingCondition` compares baselines even for a fixed version; the fixed-version rejection happens later in `handleMatch`. Never assert reachability with `getMatchingCondition` — use `acceptedVersionsOf`.
- Two mappings on the same path and method (one per version) cannot both appear in one OpenAPI document, so the ungrouped `/v3/api-docs` shows only one of them. The per-version documents at `/v3/api-docs/v1` and `/v3/api-docs/v2` are the ones clients read.
- Rewrite the `X-API-Version` parameter from an `OpenApiCustomizer`, not an `OperationCustomizer`. springdoc fills the parameter in after operation customizers run and appends its own parsed value (`1` becomes `1.0.0`), so an operation-level rewrite ends up with both values in the enum.

Update this file when configuration beans change.
